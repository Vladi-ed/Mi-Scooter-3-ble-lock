# Сообщения об уязвимостях

Не публикуйте сведения, позволяющие подключиться к чужому устройству,
ключи привязки, дампы localStorage, реальные пакеты обмена или подробные
журналы в публичных issues и обсуждениях.

Если в репозитории включена функция GitHub Private Vulnerability Reporting,
используйте **Security → Report a vulnerability**. При отсутствии этой
возможности запросите у сопровождающего приватный канал связи, не передавая
в публичном запросе детали эксплуатации или чувствительные данные.
Отдельный адрес для приватных сообщений пока не задан.

В приватном отчёте опишите затронутое поведение, условия воспроизведения,
влияние и версию приложения. По возможности используйте синтетические
имя, серийный номер и данные обмена. Перед отправкой реальных материалов
согласуйте, какие данные нужны и как их безопасно передать.

Для обычных ошибок интерфейса и подключения используйте публичный
[шаблон отчёта](.github/ISSUE_TEMPLATE/bug_report.yml) с обезличенным описанием.
Подробный журнал может содержать материал привязки даже в виде HEX
или шифротекста; скрытия текстового серийного номера недостаточно.
В обычном копировании приложение скрывает известные идентификаторы
и исключает raw-пакеты. Перед отправкой вручную проверьте весь текст;
автоматическое скрытие не гарантирует полной анонимности.

Приложение хранит настройки и привязки локально в браузере. Для удаления
ключа текущего самоката используйте «Забыть привязку»; для удаления всех
данных приложения очистите данные сайта. Копии, ранее отправленные другим
людям или опубликованные, этим действием не удаляются.
